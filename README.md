# IRON PERIMETER

Godot 4.4+ / GDScript로 만든 가로형 랜덤 디펜스 3차 프로토타입.
원작 리소스를 사용하지 않은 자체 벡터 임시 그래픽. 외부 플러그인 없음.

## Windows 실행

Godot 프로젝트 관리자에서 **가져오기 → 이 폴더의 `project.godot` → 편집 → F6가 아닌 F5**.
검증용 공식 Godot 4.4.1 포터블 엔진이 현재 PC의 `.tools`에 포함되어 있습니다(버전 관리 제외).
PowerShell에서:

```powershell
.\run.ps1           # 게임 실행
.\run.ps1 -Editor   # 편집기
.\run.ps1 -Test     # 통합 테스트 + 90초 자동 플레이
.\run.ps1 -WindowsTest # 실제 렌더링 및 10초 준비 → 첫 웨이브, 화면 입력 검사
.\run.ps1 -Balance  # 무작위/약한 시작/강한 시작 각각 100시드 + 무성장 대조군
```

실행 정책으로 스크립트가 차단되면 Godot 편집기에서 직접 실행하세요.
엔진을 별도로 설치한 경우 Godot 4 표준 버전으로 프로젝트를 가져오면 됩니다(.NET 불필요).

## 플레이

1. 실행 직후 **작전 준비 10초**가 자동 시작됩니다. 초기 **100G**, 소환 **50G**, 판매 **25G**입니다.
2. 중앙 빈 칸 클릭/터치 → **유닛 소환**(Q). 칸을 지정하지 않았거나 그 칸이 차 있으면 다음 빈 칸에 자동 배치합니다.
3. 배치된 유닛을 클릭하면 외곽선과 사거리가 표시되고, 우측 패널에서 이름·등급·공격력·공격속도·사거리를 확인할 수 있습니다.
4. 유닛 선택 → 빈 슬롯 클릭은 **무료 이동**, 다른 유닛 슬롯 클릭은 **무료 교환**입니다. 선택은 이동한 유닛을 따라갑니다. 공격 쿨다운은 유지됩니다.
5. 선택 → **판매 / +25G** → 별도 위치에 나타나는 **판매 확정**으로 판매합니다. **취소** 가능. 판매 슬롯에는 다시 소환할 수 있습니다.
6. **선택 유닛 재클릭**, **우클릭**, **ESC**, 전장/화면 빈 배경 클릭, 또는 **선택 해제** 버튼으로 선택을 해제합니다. 다른 유닛을 교환 없이 선택하려면 먼저 해제하세요. 선택 상태의 빈 슬롯 클릭은 해제가 아닌 이동입니다. 터치에서는 같은 유닛 재탭으로 해제합니다.
7. 준비 중 소환/이동/교환/판매가 가능합니다. 적이나 웨이브 타이머는 진행되지 않으며, 10초 후 유닛 유무와 무관하게 1웨이브가 시작됩니다.
8. 포탑은 사거리 내 가장 가까운 적을 자동 공격합니다. 적은 외곽을 계속 순환하며 처치 시 골드를 얻습니다. 전투 중 18초마다 새 웨이브가 시작됩니다.
9. **일시정지/계속**(Space)은 준비 카운트다운과 전투를 모두 정지/재개합니다. 정지 중 소환/이동/판매는 불가합니다.
10. 적이 60기 누적되면 패배합니다. **재시작**은 자원·선택·판매 확인·적·배치·웨이브를 초기화하고 즉시 100G / 10초 준비 단계로 돌아갑니다.

## 3차 적/경제 규칙

처치되지 않은 적은 순환 횟수와 관계없이 계속 남습니다. 다음 웨이브가 시작해도 제거되지 않습니다.
상단 숫자는 **현재 생존 적 / 60**이며 30기부터 주의, 45기 위험, 54기 붕괴 임박으로 표시합니다.
60기에 도달하는 순간 패배합니다. 정해진 웨이브나 RNG에 의한 강제 패배는 없습니다.

| 적 | 기준 체력 | 기준 속도 | 방어력 | 처치 보상 |
|---|---:|---:|---:|---:|
| 일반형 | 90 | 78 | 0 | 2G |
| 속공형 | 70 | 165 | 0 | 2G |
| 중장갑형 | 180 | 56 | 6 | 3G |
| 군집형 | 40 | 100 | 0 | 1G |

기준 값에 생성 웨이브의 체력 배율 `1.13^(웨이브-1)`, 속도 배율 `min(1+0.018×(웨이브-1), 1.45)`가 적용됩니다.
이미 나온 적의 능력치는 다음 웨이브에 소급 변경되지 않습니다.
방어력은 타격당 고정 차감하며 최소 피해는 1입니다. 시즈/랜서의 다중 타격이 군집과 중장갑에 유리합니다.
다음 웨이브 진입 시 **생존 보급 8G**를 한 번 지급합니다(첫 웨이브 제외). 처치 보상은 후반에도 증가하지 않습니다.

| 웨이브 | 일반 / 속공 / 중장갑 / 군집 | 총 출현 | 기본 출현 간격 |
|---|---|---:|---:|
| 1 | 12 / 0 / 0 / 0 | 12 | 0.85초 |
| 2 | 10 / 8 / 0 / 0 | 18 | 0.65초 |
| 3 | 6 / 6 / 6 / 12 | 30 | 0.42초 |
| 4 | 8 / 8 / 8 / 20 | 44 | 0.30초 |
| 5 | 8 / 8 / 10 / 22 | 48 | 0.26초 |

군집형은 기본 간격의 45%로 묶여 등장합니다. 6웨이브 이후 편성은 점진적으로 증가하며 상한은 82기/웨이브입니다. 이는 한 웨이브 동안 순차적으로 등장하는 수이고 동시 생존 한도는 여전히 60기입니다.

## 밸런스 검증

`tests/balance_simulation.gd`는 실제 게임의 이동·피해·소환·보상 코드를 60Hz로 호출합니다.
자동 전략은 50G마다 고정 순서 슬롯에 즉시 소환하며 판매/위치 변경은 하지 않습니다.
무작위 초기 조합 100개 시드와, 같은 후속 RNG를 사용하는 벌컨2/시즈+랜서 시작 각100개 시드를 비교합니다.
고정 초기 조합 이후 소환하지 않는 무성장 실험은 무작위 요소가 없어 각각1회만 실행합니다.
최대13웨이브 종료까지 측정하며 그 시점 생존자는 이후 패배 여부를 판정하지 않습니다.
웨이브별 평균은 해당 웨이브 종료(다음 보급 전) 또는 패배 시점의 관측치이며 도달한 표본만 포함합니다.
전체 원시 결과는 `docs/balance-results.json`, 요약은 `docs/PHASE3_RESULTS.md`에 저장합니다.
이 결과는 자동 전략에 대한 통계이며 사람 플레이의 승률이 아닙니다.

| 종류 | 확률 | 공격 |
|---|---:|---|
| 벌컨 | 55% | 0.22초 간격 단일 표적 |
| 시즈 | 30% | 1.35초 간격 반경 70 범위 포격 |
| 랜서 | 15% | 0.85초 간격 직선 관통 |

포격/탄환은 이번 단계에서는 즉시 판정 + 별도 시각 효과입니다. 이동하는 투사체·탄도 시뮬레이션은 포함하지 않습니다.

## 파일 구조와 확장

- `scenes/main.tscn`: 메인 씬. Board / Actors / Combat / Effects / Session / HUD.
- `scripts/core`: 게임 상태·웨이브·소환·경로·공격 판정.
- `scripts/entities`: Enemy의 체력과 이동, Tower의 데이터와 시각 노드.
- `scripts/data`: `UnitDefinition`, `UnitCatalog` Resource 타입.
- `scripts/data/enemy_definition.gd`, `data/enemies/*.tres`: 적 체력·속도·방어력·보상·시각 씬.
- `scripts/data/wave_director.gd`, `data/waves.tres`: 혼합 편성·출현 간격·성장률·생존 보급.
- `data/units/*.tres`: 능력치, 등급 문자열, 소환 가중치, 색상 및 그래픽 씬 참조.
- `data/unit_catalog.tres`: 소환 목록. 유닛 리소스를 추가하고 목록에 등록하면 확률에 반영됩니다.
- `scripts/visuals`, `scenes/tower_visual.tscn`: 자체 임시 그래픽·피격 효과. 유닛 `visual_scene`을 Node2D 기반 Sprite2D/AnimatedSprite2D 씬으로 교체하세요. +X가 조준 방향입니다. 선택적으로 `configure(UnitDefinition)`을 구현할 수 있습니다.
- `scripts/ui/hud.gd`: 표시·입력만 담당, Session 메서드와 signal로 연결. 현재 프로토타입 HUD는 코드로 생성됩니다.
- `tests`: 플러그인 없는 SceneTree 통합 테스트 및 자동 플레이, 프리뷰 캡처.
- `docs/IMPLEMENTATION.md`: 설계 범위 및 구현 결정.
- `docs/PHASE2.md`: 준비/이동/교환/판매 설계. `docs/PHASE2_VALIDATION.md`: 2차 검증 결과.
- `scripts/visuals/range_display.gd`: 전장 영역으로 제한된 선택 유닛 사거리 표시.
- 적 그래픽은 각 `EnemyDefinition.visual_scene`을 Node2D 씬으로 교체합니다. +X가 이동 방향이며 선택적으로 `configure(EnemyDefinition)`을 구현합니다.

신규 등급/가중치는 데이터 편집만으로 추가됩니다. 새로운 공격 방식은 `AttackKind` 및 `CombatSystem.fire`에 구현해야 합니다. HUD 소환 카드 영역은 현재 3종에 맞춘 크기이며, 콘텐츠 확장 시 스크롤 목록으로 변경하세요.

## 화면 및 iOS 준비

1280×720, `canvas_items` + `keep`: 비율을 유지하며 다른 화면에는 여백을 둡니다.
가로 방향, 터치를 마우스 클릭으로 에뮬레이션하며 키보드 없이 모든 기능을 사용할 수 있습니다.
폰트는 Windows의 맑은 고딕 / Apple SD Gothic Neo 등의 시스템 폰트를 사용합니다.
배포 단계에는 라이선스가 확보된 한글 폰트를 번들하여 플랫폼별 차이를 없애세요.

iOS 내보내기는 [Godot 공식 문서](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html)에 따라 macOS와 Xcode가 필요합니다. Windows에서 iOS 빌드·서명·실기기 검증은 하지 않았습니다.
실제 출시 전에는 노치 안전 영역, 작은 화면 터치 크기, 실제 iPhone 성능 및 발열을 확인해야 합니다.
